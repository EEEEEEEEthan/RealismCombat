# 代码优化

**终极目标：** 减少维护成本。

**子目标：** 减少类成员；每个 `private` 成员都被引用至少 2 次。

不要为了拆而拆长方法；仅当片段可复用时才抽取。

C# 特定规则
[entries/csharp.md](entries/csharp.md)

## 优化检查清单

执行代码优化时，按以下清单逐项检查：

### 通用规则

- [ ] 移除冗余逻辑（未被调用过的逻辑）
- [ ] 封装，复用重复代码片段
- [ ] 仅被引用过一次的方法，应该成为内联实现或者成为闭包方法
- [ ] 对外优先保留单一入口（如 `MarkXxx` 同时表达设置与清除），避免并行维护 `SetXxx`/`ClearXxx` 双接口
- [ ] 事件处理器如果只被订阅一次，应该内联为 lambda 表达式以减少类成员
- [ ] 仅被一个方法调用过多次的方法，应该成为内部方法
- [ ] 高频方法里的内部方法应该尽量用 `static`
- [ ] 移除所有多余空行
- [ ] 文档注释不要出现具体数值,应该用参数/字段/属性/方法名来描述
- [ ] 检查所有元素（类、字段、属性、方法等）命名；局部命名直接改，`public` 元素提出更好方案后再改
- [ ] 布尔参数避免否定命名（如 `dontXxx`），改用肯定语义（如 `deferXxx`、`initializeImmediate`）
- [ ] 充分利用最新版本的语言特性去简化代码
- [ ] 仅被引用过一次的编译期常量，应该内联到使用处（例外：若有缓存意义，如字典、集合等需要避免重复创建的数据结构，应保留）
